# 管理页功能指南

日常任务在 Agent 的聊天里提出。管理页用于配对浏览器、管理 Agent 授权、查看标签组和核查操作；手工任务与流程位于“高级管理”。

## 打开管理页

运行 `saltedfish dashboard`。Windows 默认打开浏览器，其他系统打印一次性登录链接和短码。也可从已配对扩展点“打开管理页”；有管理授权时进入已登录页面，没有时进入登录页。

登录码 5 分钟内有效、只能用一次。管理页会话空闲 30 分钟或达到 12 小时后失效，服务重启也会失效。点“退出管理页”撤销当前会话；`saltedfish dashboard --logout-all` 撤销全部会话。不要转发登录链接。完整登录步骤见[安装与运维](npm.md)。

## 浏览器：配对、命名与暂停

每个 Chrome 用户配置分别加载扩展、配对并命名。名称用于辨认，不证明网站登录身份；不同配置使用独立持久身份。同一配置中的多个窗口共享网站登录态。

“浏览器”页显示在线状态、扩展版本和连接提示。离线时保留身份与记录，不会自动换用另一配置。

- **新增浏览器：** 输入名称，生成配对码，粘贴到对应 Chrome 的扩展中连接。是否允许该浏览器打开已登录管理页，单独授权。
- **撤销管理权限：** 只撤销该配对的管理能力，不等于撤销浏览器配对。
- **撤销配对：** 断开该浏览器，保留网站登录和原身份。
- **重新连接：** 扩展重装或换加载目录后，在原离线浏览器卡片换发配对码。未配对扩展可接回原身份、名称、Agent 授权和记录。在线浏览器不能替换；旧配对随之作废。
- **移除：** 不再使用的离线配置可移除，配对也作废。有结果不明记录时先按恢复流程处理。

扩展“暂停所有 Agent”仅暂停当前 Chrome 配置。暂停后需要在同一扩展恢复连接。手动停止 Chrome 调试也会暂停；可选的“1 分钟后自动恢复连接”默认关闭。暂停不能撤回已经发出的动作。

## Agent：独立授权与使用状态

在“Agent 连接”新增授权，明确选择一个浏览器，或允许全部当前及未来浏览器，并选择只读或允许操作。再选择客户端，将生成的配置导入服务所在电脑上的 Agent。`/mcp` 只接受同机连接；Chrome 扩展可以在其他电脑。

也可通过“主机辅助配置”或 `saltedfish connect` 自动接入。这只检测和修改服务主机上的客户端配置，不会配置其他电脑。审批差异见[支持的客户端](supported-clients.md)和[一次信任](once-trust.md)。

已授权不等于在线，MCP 已连接也不等于正在使用浏览器：

| 状态 | 含义 |
| --- | --- |
| 使用中 | 正在操作、占用标签页，或最近 30 秒操作过页面 |
| 待命 | 会话连接着，当前没有操作 |
| 未连接 | 有授权，但没有有效连接 |
| 状态未知 | 无法确认连接状态，不应当作在线 |

同一个 Agent 的多个会话聚合展示。机器名、IP 和来源登记仅用于辨认，不参与授权判断。界面显示操作类别，不展示脚本、输入内容或请求正文。

每个 Agent 的“高级工具”开关控制默认工具目录：默认 46 个，开启后 64 个，重连生效。任务和流程工具位于高级目录；关闭目录展示不等于撤销权限。

“撤销授权”阻止后续调用，但不能撤回已派发操作。“访问权限”页也可核对授权范围与撤销状态。

## 标签组：看清并交还工作范围

一个 MCP 会话在每个窗口最多有一个 Agent 标签组。`chrome_new_tab` 和 `chrome_claim_tab` 会建立工作范围；已有页面写入前应先接管，读取仍受浏览器授权限制，但不要求进组。

- Agent 只能写入自己创建、接管的标签页，以及这些页面打开的链接和弹窗。
- 其他会话占用的标签页不能写入或接管。
- 把标签页拖出 Agent 组表示收回。后续写入返回 `TAB_TAKEN_BACK`，也不能再次接管；拖回原组可恢复。
- 仅把标签页拖进组不算授权，仍需由 Agent 明确接管。
- 固定标签页、已有用户标签组里的标签页和弹窗不会为建组强行移动，但接管后仍受占用协调。

可在管理页或扩展中“显示标签组”“结束并释放”。结束时解散组、释放占用，标签页保留；接管来的标签页尽量放回原位。若会话仍连接，下次开页可重新建组。这不是永久禁用 Agent，需阻止访问时应暂停或撤销授权。

标签组是协调边界，不是安全隔离：获授权的 Agent 仍可接管空闲页面。重连后只有在同一 Agent、同源、没有其他占用等条件满足时才自动接回原页，并带 `TAB_REJOINED` 提示；否则需重新接管。

Chrome 可能保存组名和组内网址。退出 Chrome 时仍打开的组可能留下记录，需在 Chrome 标签组列表整理。数据影响见[限制与数据说明](beta-limitations.md)。

## 操作提示与后台标签页

扩展的“Agent 操作时显示它的光标”（`showCursor`）默认开启。光标和目标框画在 CDP Overlay，不往页面 DOM 或主世界添加元素；截图前收起。它只显示位置，不派发输入。Agent 在后台标签页操作时，切过去才看得到。

“像真人一样移动鼠标、打字”（`humanInput`）也默认开启。鼠标沿轨迹移动、停顿和按住；短的 US 键盘文本逐键输入，中文或长文本仍可能整段插入。用途是按真实用户节奏输入，兼容依赖悬停、按住和拖拽时序的页面。每次点击会多约 0.4–1 秒，可在扩展关闭。

视觉动作通常不切换用户正在使用的标签页。后台截图失败时可能短暂切到前台再切回；最小化窗口会临时恢复。不要在同一目标页面同时手动输入；需要接管时先暂停扩展。

## 操作记录与结果不明恢复

操作记录包含工具、目标、时间、状态和操作标识。点击成功只代表工具步骤完成，不证明订单、付款或网站事务成功。动作结果里的 `pageChange` 和核验条件用于确认页面变化，详细字段见[交互说明](interaction.md)。

区分三种情况：

| 结果 | 处理 |
| --- | --- |
| `outcome: "not_dispatched"` | 已证明动作未派发；修正前置条件后可重试，不制造结果不明保护 |
| `outcome: "dispatched"` | 动作已发出，但后续核验未通过；不要重复该动作。不会仅因此隔离标签页，队列任务仍需核查 |
| 结果不明 | 超时、断线或崩溃后无法确认实际结果；阻止相关目标的新写入，先检查页面 |

带标签页的结果不明只阻止该标签页写入；影响范围不明的配置级操作会阻止整个配置写入。保护期间仍可进行允许的只读核对。

恢复步骤：

1. 打开原 Chrome 配置，查看真实页面、下载状态和操作记录。
2. 核对哪些动作已经发生，必要时截图，不要重放整段任务。
3. 对每条结果不明操作明确确认，再解除保护。Agent 可用 `chrome_operations` 查询、`chrome_recover_operation` 确认。
4. 若要继续任务，重新明确目标，只提交尚未执行的步骤。

确认只解除保护，不重放动作，也不让已结束任务自动继续。原配置离线时不能按常规流程确认。

### 永久丢失的浏览器配置

离线超过 24 小时或没有最后在线时间的配置，管理页可提供“放弃此配置…”。只在确定原配置不会再连接时使用；暂时关机或休眠应等待原配置恢复。

对话框列出待核查记录，要求输入总数确认。服务会拒绝在线配置、仍有运行操作或数量已变化的请求。放弃只确认数据库中的结果不明记录并移除配置，不连浏览器、不重放动作、不取消已有暂停或待核查任务。此动作没有 MCP 工具，Agent 不能自行放弃保护。

### 存储故障

业务已完成但结果保存失败时，保留业务结果并单独警告，不应据此重试。完成日志写入失败会带 `OPERATION_JOURNAL_FAILED`，相关写入继续受保护。先核对页面、修复磁盘或目录权限，再重启并显式恢复。

“导出诊断”不包含运行参数、脚本或图片，但名称和环境信息仍需检查。未登记的历史结果文件会计入容量，不自动删除。

## 任务队列：高级管理

任务是明确选择浏览器和标签页后提交的一组步骤。目标失效时保持未选择，不会回退到其他标签。动作、等待与核验可组合；需要跟随新标签页时，按来源及提交前基线匹配，不选择第一个弹窗。

Agent 可用 `chrome_task_submit` 提交、`chrome_task` 查详情、`chrome_tasks` 看队列、`chrome_task_control` 暂停、继续或取消。任务自行管理租约，提交前应释放同步工具持有的占用。

- 每个浏览器配置串行，最多 4 个配置并行。
- 每配置最多 20 项待处理，全局最多 100 项；每任务最多 200 步。
- 单计划最多 2 MiB，驻留计划总计最多 32 MiB；任务终态历史最多 500 条。
- 暂停和取消在当前步骤结束后生效，已派发的点击、上传或网站请求不能撤回。暂停中的任务不持有浏览器租约。
- 任务绑定提交时的连接代际。Chrome 重连后，不把旧任务尾部发给新连接，即使配置和标签编号相同。
- 失败停止后续步骤，并暂停该配置的排队任务；其他配置继续。已派发但核验失败或结果不明时进入 `needs_review`，不自动重试写入。
- 服务重启后，残留任务标为 `interrupted`。运行计划和参数不从历史恢复，需要核查后新建剩余任务。

记录写入失败时，队列进入存储保护，拒绝新增或继续。已发出的动作可能完成，已知成功不会被改成未执行。修复存储后重启，再明确编辑剩余步骤。

“核查后编辑剩余步骤”只载入草稿，不执行、不解除保护。它要求选择起始步骤、重新输入参数并核查页面；目标标签页留空，必须重新选择。已保存流程使用提交时的历史版本，普通任务生成需重新填写的步骤。

## 流程：保存与版本管理

流程是主动保存的任务定义，不是后台录制器，也不是模型 skill 管理器。每个流程固定属于一个浏览器配置；跨配置使用应明确复制，且同时拥有源和目标配置的授权。

可在文字、URL 和定位条件中使用 `{{日期}}`、`{{query}}` 等参数。运行前填写参数，预览展开后的步骤再入队；修改参数后重新预览。每次预览只用于一次入队，防止连续点击重复提交。

- 不在流程里写死密码或令牌。识别为敏感字段的文字常量会被 `WORKFLOW_SECRET_LITERAL` 拒绝，应改用参数；名称看不出敏感含义时可能拦不住。
- 脚本表达式不支持参数插值，临时 `ref`、`dialogId` 和 iframe `contextId` / `sessionId` 不能作为可复用定位保存。
- 参数只用于运行，不写入任务审计。流程定义是持久数据；故障截图可能包含表单内容。
- 编辑保存创建新版本；恢复旧版也创建新版本，不覆盖历史。其他客户端已修改时拒绝过期编辑。
- 已提交任务保留提交时计划，不随流程编辑变化。
- 归档后不能运行；恢复不消耗内容版本。永久删除只允许已归档流程，并需再次确认，定义和历史不可恢复。

活动流程最多 100 个，归档最多 1000 个；单定义最多 2 MiB，每流程最多 50 个内容版本，版本历史总计最多 64 MiB。超过版本上限可复制为新流程；删除前按需导出，导出文件可能包含主动保存的敏感内容。

## 结果与配置备份

大 JSON、图片和任务故障截图保存在服务数据目录，受容量预算限制。任务详情可查看关联结果；`saltedfish results list` 列出结果，`saltedfish results remove ARTIFACT_ID` 永久删除选定结果，不会批量自动清理。

客户端接入前会备份原配置；可在接入页或 `connect --history` 中查看，使用 `connect --restore ID` 恢复。文件存在后续修改时拒绝覆盖，备份最多 100 份。不要分享原始备份，其中可能包含其他服务凭据。
